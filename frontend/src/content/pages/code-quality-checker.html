How the grade is actually calculated

Five weighted components, computed from real metrics — not a black box.

Complexity density — 35%

Cyclomatic complexity relative to lines of code. The single biggest factor in the grade.

Average function length — 25%

Scored against a 15-line reference for healthy code and a 60-line reference for code that needs splitting up.

Comment coverage — 20%

Comment lines relative to code lines, scored against a 20% reference for well-documented code and 2% for under-documented code.

TODO density — 10%

TODO/FIXME markers relative to code lines — a small weight, but a real signal of deferred work piling up.

Nesting depth — 10%

Your deepest function's nesting, scored against a reference of 3 (good) and 8 (bad). Often the fastest single thing to fix once you spot it.

A–F letter grade

The five weighted scores combine into one 0–100 number: A at 90+, B at 80+, C at 70+, D at 60+, F below that.

Frequently asked questions

Can I see why I got a specific grade, not just the letter?

Yes — the report's Scoring tab breaks the grade down into all five components above. See reading a code health score for a full walkthrough.

Is the grade per-file or per-project?

Both. The overall grade rolls up the whole repository; the Files tab shows the same underlying metrics per file, so you can find exactly which files are pulling the grade down.

Does it check test coverage too?

Optionally — upload an LCOV report from your own CI run and REPO-SIGHT correlates line coverage against the files that need it most. It doesn't run your test suite itself.

Which languages get a health score?

All six: C++, Python, Java, TypeScript, JavaScript, and C#, each scored with their own language-specific metrics.
