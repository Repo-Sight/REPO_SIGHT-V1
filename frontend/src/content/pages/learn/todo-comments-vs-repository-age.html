The longest Java methods in 13 open-source projects

← Back to Learn

Only 0.15% of the Java methods and constructors in 13 respected open-source projects are longer than 100 lines — 211 out of 140,090. We ranked the longest of them. The ten longest are all in test or benchmark code, and 159 of the 211 (75%) sit outside production paths. The long methods that do ship in production are a small, recognisable set.

How we measured

The projects are Guava, Guice, Gson, Jackson Core, Jsoup, Joda-Time, JUnit 5, Mockito, Retrofit, SLF4J and three Apache Commons libraries (Collections, IO and Lang). Each was scanned at a pinned commit listed in the open data file. Only Java files are counted, so Retrofit’s bundled website scripts are left out. Length is the number of lines from a method’s first line to its closing brace, and a constructor counts as a method. “Non-production” means a path with a directory named like test, tests, benchmark, examples, docs or vendor, or a file named like FooTest.java.

How rare is a long method?

  • The median method is 5 lines. One method in a hundred is longer than 50 lines.
  • 1,340 methods (1.0%) are over 50 lines, 211 (0.15%) are over 100, and 49 are over 200.
  • The count is concentrated: Guava has 66 of the 211, Jackson Core 37, Commons Lang 30, Guice 26, Joda-Time 12 and Gson 9.

The longest of all: tables and test bodies

The top of the ranking is not code anyone would call logic:

  • Jackson Core, DoubleToDecimalChecker: four methods named hard0 to hard3 of 5,004, 5,004, 5,004 and 4,549 lines. Each returns a single array of hard-coded double-precision values for a test.
  • Commons Lang, ArrayUtilsTest.testSameLengthAll: 1,334 lines of setup and assertions in one test method.
  • Guava, CharMatcherBenchmark: populateProb2 at 720 lines and populateProb1 at 633, both in benchmark code.
  • Commons Lang, SystemUtilsTest.testJavaVersionMatches: 623 lines.

All of the ten longest methods, and 19 of the 20 longest, are in tests or benchmarks. They are long because they list data or repeat one kind of assertion many times, not because they are tangled. Another 20 of the 211 are methods named suite, the JUnit 3 convention for collecting tests.

The longest production methods

Filtering to production paths leaves 52 methods over 100 lines. The longest are:

  • Retrofit, RequestFactory.parseParameterAnnotation: 456 lines — parses the annotations on a parameter.
  • Jsoup, HtmlTreeBuilderState.inBodyStartTag: 357 lines — the HTML parser’s rules for start tags inside the body.
  • Mockito, MockMethodAdvice.wrap: 257 lines — bytecode advice for mocked methods.
  • Guice, FactoryProvider2.FactoryProvider2: 227 lines — a constructor.
  • Guice, SingletonScope.scope: 223 lines — singleton scope handling.
  • Guice, BindingProcessor.visit: 217 lines — binding processing.
  • Mockito, MockMethodAdvice.visitCode: 205 lines — bytecode advice for mocked methods.
  • Commons Lang, RandomStringUtils.random: 202 lines — random string generation.

Read down that list and the pattern is clear: parsers and annotation handlers, bytecode instrumentation, and framework internals. Retrofit’s parseParameterAnnotation is an if/else-if chain with one branch for each annotation type, such as Url, Path and Query. Jsoup’s inBodyStartTag follows the HTML specification’s rules for start tags, which are themselves a long list of special cases. In both, the length mirrors the thing being modelled.

Complexity points the same way. The most complex production methods are Jsoup’s inBodyStartTag at 124, Retrofit’s parseParameterAnnotation at 120, and Commons Lang’s random at 78. Across all 984 Java methods above complexity 10, 344 (35%) are in non-production paths.

What this means for your own code

  • Check the path before the number. A test with a 1,300-line body is a different problem from a 300-line method in production code.
  • Long and branchy often means “mirrors a spec”. If a method follows an external grammar or protocol, the useful questions are whether it is tested and whether a new case is easy to add.
  • Tables belong in data. A method that returns thousands of literal values is a candidate for a resource file.
  • Set a limit and watch the trend. Projects this well maintained still have a few dozen long production methods. Zero is not the goal; a steady count is.

Frequently asked questions

Are constructors counted as methods?

Yes. Guice’s FactoryProvider2 constructor, at 227 lines, is in the list above.

Why is the share so low compared with other languages?

In this data set, 0.15% of Java methods pass 100 lines, against 1.2% of C++ functions and 0.45% of Python functions. These are 13 mature projects with strong conventions, so treat it as a picture of well-kept code and not a language ranking.

How do I find the long methods in my project?

Paste a GitHub URL and the report ranks your longest and most complex methods by file. The Java code analyzer page lists what is checked, and how to improve Java code quality shows common fixes.
