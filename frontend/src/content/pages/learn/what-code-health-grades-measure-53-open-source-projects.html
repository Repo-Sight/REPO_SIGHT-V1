What code health grades look like across 53 open-source projects

← Back to Learn

We scanned 53 well-regarded open-source projects and graded each one with REPO-SIGHT’s code health score. The result: 15 As, 13 Bs, 22 Cs, 3 Ds and no Fs. Two of the five score components decide almost every grade, and the language a project is written in moves the result far more than most people expect. A C in this data set rarely means the code is bad.

How the score works

The score is a weighted average of five components, each scaled from 0 to 100 between a “good” and a “bad” reference point. Reading a code health score covers the idea in detail. The figures below come from the scoring code itself:

  • Complexity density (35%): cyclomatic complexity per line of code, from 0.15 (full marks) to 0.50 (zero).
  • Average function length (25%): from 15 lines (full marks) to 60 lines (zero).
  • Comment density (20%): comment lines per code line, from 0.20 (full marks) down to 0.02 (zero).
  • TODO density (10%): TODO and FIXME markers per code line, from 0.01 (full marks) to 0.05 (zero).
  • Maximum nesting depth (10%): from 3 levels (full marks) to 8 (zero).

Grades are A at 90 and above, B at 80, C at 70 and D at 60. We recomputed every project’s score from the published columns of the open data file and matched each one to within a tenth of a point.

The distribution

The 53 projects split into 15 As (28%), 13 Bs, 22 Cs and 3 Ds. The top scorers are SLF4J (94) and Jsoup and Polly (92 each). The three Ds are axios (70), fastapi (70) and core (69). All three are within two points of a C. In fact 18 of the 53 projects score within one point of a grade boundary, so a single refactor or a pile of new comments can move a grade.

Two components decide the grade

Averaged over the 53 projects, here is how many of the 100 points each component costs:

  • Maximum nesting depth: 9.7 of 10 points lost. 48 of 53 projects score zero on it, because their deepest block is eight levels or more. The median project’s deepest block is 10 levels.
  • Comment density: 8.0 of 20 points lost.
  • Average function length: 0.8 of 25 points lost.
  • Complexity density: 0.1 of 35 points lost.
  • TODO density: 0.0 of 10 points lost.

Because nesting depth is a near-constant penalty — almost every large project has at least one deeply nested block — it barely separates one project from another. Comment density does. The average A-grade project scores 100 on comments, the average C-grade project scores 26, and the three Ds average 17. Complexity and TODO density cost almost nothing across these projects, which fits their reputation for well-maintained code.

The practical reading is that a project’s grade here is mostly its comment density, with a fixed deduction for the one deeply nested block everyone has.

Why the language matters so much

  • Java: 13 projects, average score 90, grades 11 A and 2 B. Comments average 45 per 100 lines of code.
  • C++: 14 projects, average 84, grades 3 A, 7 B and 4 C. Comments average 19 per 100 lines.
  • JavaScript: 5 projects, average 76.
  • Python: 18 projects, average 74, grades 2 B, 15 C and 1 D. Comments average 5 per 100 lines.

The gap is mostly comment density, and part of it is a counting convention. REPO-SIGHT counts only # comments as comment lines in Python. We checked this with a small test file: a function with a three-line docstring and one # comment reports one comment line and six code lines. Python projects document themselves in docstrings, so they score low on this component even when they are thoroughly documented. Javadoc blocks in Java and // comments in C++ count in full.

The lesson is to compare a project with other projects in the same language. A Python project at 74 is a normal result; a Java project at 74 would be unusual.

How to use your own grade

  • Open the breakdown, not just the letter. The component scores tell you which of the five is costing points.
  • Pick the component you can move. Splitting one very deep block is a quick win for nesting depth. Adding useful comments moves comment density, but only if the comments help.
  • Track the change between scans. Moving from 69 to 72 matters more than the letter.

Frequently asked questions

Is a C a bad grade?

Not on its own. In this data set 22 of 53 respected projects score a C, and the cause is usually comment density or one deep block, not tangled logic.

Why is there no F?

An F needs a score below 60. The lowest project here scores 69. Complexity density and TODO density are almost always strong in mature projects, which sets a high floor.
