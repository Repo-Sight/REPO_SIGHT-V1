What this isn't

Some "repository health" tools score how active a GitHub repo looks: commit frequency, issue counts, README completeness, stars and forks. REPO-SIGHT does something different.

It reads the actual code

A real lexer and parser walk your source files — the report is built from cyclomatic complexity, nesting depth, and rule violations, not GitHub API activity metadata.

Five-stage pipeline

Scan → lex → parse → aggregate → report. The same deterministic pipeline the underlying engine runs from the command line.

No GitHub App, no OAuth required to scan

Paste a URL and get a report — no app to install, no repository access to grant. Signing in is optional and only adds scan history.

Every tab, one scan

Overview, By Language, Files, Duplication, Coverage, Security, and Scoring — all from the same free pass over your repo.

Frequently asked questions

Does it need a GitHub App installed on my account?

No. Just paste a public repository URL — no app install, no permissions grant.

Does it use the GitHub API to score commit activity?

No. REPO-SIGHT clones the repository and parses the source files directly; commit frequency, star count, and issue activity aren't part of the score.

Can I analyze a private repository?

Not yet — only public repositories on the main/master branch are supported today.

How long does a scan take?

Best for repositories that analyze in under a minute; very large repos can exceed the time budget and time out rather than return a partial report.
