Frequently asked questions

Is REPO-SIGHT really free?

Yes. There are no tiers and no paywalled metrics. A small amount of advertising pays for hosting. Sign-in is optional for public repositories and required for private ones.

Does it run my code?

No. It only reads source files. Nothing is built, executed, or tested, and repository scripts are never run, so a flagged command or eval() is reported, not triggered.

Which languages does it analyze?

C++, Python, Java, TypeScript, JavaScript, and C#. Other languages found in a repo are listed in the report as not analyzed, so the numbers never claim to cover files they skipped.

What can I scan?

Paste a public GitHub repository URL, or paste or upload a single source file of up to 2 MB. Repository scans have a time limit of about 55 seconds, so very large repos may return a “too large” message. Private repositories need a GitHub sign-in, and the sign-in token is not stored.

Do I need an account?

Only for private repositories. For public ones, sign-in is optional; signing in with GitHub also saves your last five scans and shows what changed since your previous scan of the same repo.

How accurate are the findings?

They are heuristics from a token-based parser, so some will be false positives. Each finding shows a confidence level so you can start with the ones most likely to be real. See the limits above.

What should I fix first?

Start with the Fix First list at the top of the report’s Overview. It groups findings by cause and ranks them by tier, confidence, and how many places they appear. Then check the nesting and function-length numbers in the score breakdown.

Can I see a report before scanning my own code?

Yes. Open the sample report, a real scan of REPO-SIGHT’s own source. Nothing to paste.
